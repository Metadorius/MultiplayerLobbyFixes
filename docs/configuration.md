# Configuration

Every setting is in the file the mod writes, `BepInEx\config\com.kerbiter.multiplayerlobbyfixes.cfg`, and in the Configuration Manager window (F1) while the game runs.

| Section | Key | Default | Meaning |
|---|---|---|---|
| Server browser | `ListUnreachableServers` | `true` | List the dedicated servers that do not answer this machine's rules or ping queries instead of dropping them. Their ping, mission, map, duration and player columns stay empty, and the password filter still applies. They are also held out of the game's ping loop until they answer something or a later master list reaches them |
| Server browser | `ListBeforeAnswering` | `true` | List a server as soon as Steam's master list returns it, before its rules query comes back. The row starts with the name, player count and password flag the master list holds, and fills in as answers arrive |
| Server browser | `KeepServersListed` | `true` | Keep the rows already on screen when refreshing, instead of clearing the list and adding back only the servers that answer. A refresh that returns nothing leaves the list as it was, and the servers survive leaving the multiplayer screen and coming back. Changing a filter still clears it |
| Server browser | `JoinFullServers` | `true` | Leave the Join button in the server details window clickable when the player count says the server is full. That count is what the server last registered with Steam, so it is often stale |
| Server browser | `ShowLatestQueryStatus` | `true` | Show the ping query's state in the ping column: a pulsing icon while a query is waiting for an answer, and a warning triangle with a tooltip once the last query came back empty. A response with no real ping in it counts as empty, and so does a rules response that carried no mission and no map. Servers the ping loop never asks, like the unreachable ones listed from the master list, keep the triangle. The mission cell shows the same for the rules query, which carries the map and the mission. Both markers also appear in the details window, on its ping and mission rows |
| Server browser | `RefreshServerButton` | `true` | Add a Refresh button to the server details window, left of Join, which asks that one server for its rules and its status again: the mission, the map, the description, the duration, the player count and the ping, without touching the rest of the list. Two queries per press |
| Server browser | `ThrottleQueries` | `true` | Hold the game's per-server queries in a queue and start them one at a time, instead of letting a refresh start them all at once; the game's own ping loop waits in the queue too. A query the game cancels while it waits is dropped. With this off every query starts at once |
| Server browser | `QueriesPerSecond` | `120` | How many queries a second the mod lets go out, the game's held queries and its own asks together. Each frame takes what its own time is worth, worked out from the smoothed frame time, so the rate is the same whatever the frame rate is. Lower it to be gentler on servers and on Steam, at the cost of a refresh press taking longer. Range 1 to 1000 |
| Server browser | `RefreshCooldownSeconds` | `3` | How long one server's refresh is left alone before another may start for it. A second press within that window is refused, because the first is still out and asking again would spend a second pair of queries on the same server. Range 0 to 60 |
| Server browser | `RefreshTimeoutSeconds` | `10` | When a refresh whose answers never came is given up on. Its unanswered queries are cancelled then, and the row keeps what it already had. A live server usually answers in well under a second. Range 1 to 120 |
| Server browser | `MarkerTimeoutSeconds` | `10` | When a query that never called back is written off, which stops a row's marker waiting forever on a server Steam forgot about. Range 1 to 120 |
| Diagnostics | `VerboseLogging` | `true` | Log what the browser and the Steam joins are doing |
